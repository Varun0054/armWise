# API

Local REST API served by the Python/FastAPI backend on `http://localhost:8000`, consumed by the Flutter UI. Everything here runs on-device — there is no external network call in this API's implementation.

> These endpoint names/shapes are a proposed starting contract based on the SRS functional requirements (FR-1–FR-11) and are not yet frozen — adjust as the UI and backend co-evolve.

## Scan endpoints

### `POST /scan/exe`
Analyze a dropped `.exe` file. *(FR-1)*

**Request:** `multipart/form-data`, field `file`

**Response:**
```json
{
  "application": "ExampleApp.exe",
  "evidence": { "...": "see DATABASE.md evidence object" },
  "category": "Uncertain",
  "retrieved_cases": [
    { "application": "Game A", "similarity": 0.91, "observed_result": "fails", "source": "...", "source_date": "2026-06" }
  ],
  "explanation": "string, generated by local LLM"
}
```

### `GET /scan/installed`
Enumerate and classify all installed applications (Registry + PE inspection). *(FR-2)*

**Response:** array of scan result objects (same shape as above), plus a summary block.

### `GET /scan/store`
Enumerate installed Microsoft Store apps and their declared architecture via Package APIs. *(FR-3)*

**Response:** array of scan result objects. `evidence.detection_confidence` may be `"declared"` instead of `"best-effort"` since Store metadata declares architecture directly.

## Reasoning endpoints

### `POST /ask`
Free-form follow-up question about a specific scan result or the system-wide summary. *(FR-8)*

**Request:**
```json
{ "context_id": "scan-result-id or 'system-summary'", "question": "Why does Photoshop work but this VPN doesn't?" }
```

**Response:**
```json
{ "answer": "string, grounded only in evidence already shown for that context" }
```

## Dashboard endpoints

### `GET /dashboard/summary`
System-wide health counts after a bulk scan. *(FR-10)*

**Response:**
```json
{ "native": 12, "likely_compatible": 30, "uncertain": 8, "high_risk": 3, "total": 53 }
```

### `GET /dashboard/alternatives/{application_id}`
Suggested ARM64-native alternatives, sourced only from the Knowledge Base. *(FR-11)*

**Response:**
```json
{ "alternatives": [ { "application": "AlternativeApp", "source": "...", "source_date": "..." } ] }
```

## Error handling

All endpoints return `insufficient_evidence: true` in the response body rather than a 4xx/5xx when the Knowledge Base has no comparable case — this is expected behavior (NFR-4), not a failure state. Actual errors (malformed file, backend unavailable) use standard HTTP status codes with a `detail` message.

## Backend selection

Which inference backend (`cpu` / `qnn`) serves `/scan/*` and `/ask` is controlled by `backend/config.yaml` — see [`SETUP.md`](SETUP.md). The API contract is identical regardless of backend; only latency and (until NPU-validated) output quality differ.
